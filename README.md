# device_db

電子部品の情報を集約・参照するための DB サーバを実装するリポジトリです。

## 目的

回路設計・試作・在庫管理で参照する部品情報を、一箇所にまとめて扱えるようにします。  
まずは軽量なデモ機で、登録・参照・検索の流れを確認できるところまで作ります。

## コンセプト設計

### 初期デモの方針

最初のゴールは、本格 DB ではなく **動くデモ** です。

| 項目 | 選択 |
|------|------|
| サーバ | Flask（Python） |
| データ保存 | JSON ファイル + 添付ファイル領域 |
| フロント | Flask テンプレート + vanilla HTML/CSS/JS |
| UI 言語 | 日本語 |
| 想定利用 | 単一ユーザー・デスクトップ優先 |
| 目的 | CRUD / 検索 / フィルター / ソート / ファイル添付の動作確認 |

JSON をデータストアにすることで、依存を減らし、中身を直接確認・編集しやすくします。  
デモで固まったデータモデルを、将来の本格 DB へ移行する前提です。

### デモの完了条件

次が動けばデモ完了とします。

- 部品の一覧・新規・編集・削除
- 検索バー・インラインフィルター・カラムソート
- 表示カラムのユーザ設定
- 設計事例などへの PDF / PNG 添付（アップロード・プレビュー・ダウンロード）

### データモデル

#### システムフィールド（全レコード共通）

| キー | 必須 | 内容 |
|------|------|------|
| `id` | ○ | UUID（内部一意キー） |
| `name` | ○ | 名称（UI 表示名） |
| `created_at` | ○ | 作成日時（ISO 8601） |
| `updated_at` | ○ | 更新日時（ISO 8601） |

ユーザ定義カラムは `id` / `name` / `created_at` / `updated_at` / `assigned` 以外のキーとして保持します。  
`assigned` は、その部品の詳細に表示するカラムキーの配列です（割り当て済み項目のみサイドシートに出す）。

#### 値の扱い

| ルール | 内容 |
|--------|------|
| 必須 | **名称（`name`）** のみ（`id` と日時はサーバが付与） |
| 空欄 | 未入力はキー省略、または `null`。API はどちらも受け付け、保存時はキー省略に正規化 |
| 削除 | **物理削除**（デモ）。関連添付ファイルも削除する |

#### カラム定義（全体カタログ）

カラム追加は **部品ごとではなく、全体のカラム定義に追加** します。  
各部品は、値があるカラムだけをレコードに持ちます（スパース）。

カラム定義の例:

| キー | 内容 |
|------|------|
| `key` | 内部キー（英数字・アンダースコア） |
| `label` | UI 表示名（例: メーカー、設計事例） |
| `type` | `text` / `number` / `file` |
| `order` | 表示順 |

初期から用意する想定カラム（いずれも任意・値は空欄可）:

| 領域 | 例 |
|------|----|
| 識別 | メーカー、型番、カテゴリ |
| 電気特性 | 定格電圧・電流、許容差、パッケージ |
| 調達 | 仕入先、単価、在庫・リードタイム |
| 資料 | データシート URL、社内メモ、関連リンク |
| 設計事例 | ファイル型（PDF / PNG） |

データ入力時に新しいカラムを追加可能です。追加すると全体カタログに登録され、以降の部品でも使えるようになります。

### ファイル格納

| 項目 | 方針 |
|------|------|
| 対象形式（初期） | PDF、PNG |
| 件数 | **1 カラムあたり複数ファイル可** |
| サイズ上限 | **1 ファイル 10MB**（デモ） |
| 紐づけ | 部品 ID + カラムキーにファイルを関連付ける |
| 保存 | メタデータは JSON、実体は `data/uploads/` 配下 |
| メタデータ例 | 元ファイル名、保存パス、MIME、サイズ、登録日時 |
| レコード削除時 | 関連ファイルも削除 |
| UI | サイドシートからアップロード・プレビュー・ダウンロード |
| 一覧での表示 | ファイル有無が分かるアイコン、または件数表示 |

### UI / UX

テーマは **シンプルで扱いやすい** ことです。画面数や装飾を抑え、部品の閲覧・編集に集中できる操作にします。  
**デスクトップ優先**。モバイルは最低限崩れない程度とし、専用最適化はデモ対象外です。

| 要素 | 方針 |
|------|------|
| 検索 | **検索バー** で、テキスト系カラムを横断検索（`name` を含む） |
| フィルター | カラムごとの **インラインフィルター**（テキストは部分一致） |
| 併用 | 検索バーとインラインフィルターは **AND** |
| 部品一覧 | **infinite scroll**（ページ送りなし） |
| ソート | カラム見出しクリックで昇順 / 降順を切替。**単一カラム** ソート |
| 空欄のソート | 空欄は末尾 |
| 型つきソート | `number` は数値として、それ以外は文字列として比較 |
| 一覧カラム | 水平スクロール対象の表示カラムをユーザが設定（**ドラッグハンドルで順序変更**） |
| 必須表示 | **名称・更新日は常に表示**（非表示不可。更新日は編集不可） |
| 表示設定の保存 | **localStorage**（表示／非表示と順序） |
| カラム管理 | 専用画面で名称変更・削除・新規作成・カタログ並び替え |
| 詳細・編集 | 行クリックで **サイドシート**（**割り当て済み項目のみ**表示） |
| 新規登録 | 「新規」ボタン → 空のサイドシート |
| 項目割り当て | サイドシートで **既存カラム追加** または **新規作成して追加** |
| 削除 | 確認ダイアログのうえ実行 |
| 空状態・エラー | 一覧ゼロ件や失敗時は短いメッセージを表示 |

```text
┌─────────────────────────────┬──────────────────┐
│  検索バー / 新規ボタン      │  サイドシート    │
│  部品一覧（infinite scroll） │  ・詳細 / 編集   │
│  ・インラインフィルター      │  ・カラム追加    │
│  ・カラムクリックでソート    │  ・ファイル添付  │
│  ・表示カラムはユーザ設定    │  ・保存 / 削除   │
│  ・水平スクロールで閲覧      │                  │
│  ・行クリックで詳細を開く    │                  │
└─────────────────────────────┴──────────────────┘
```

### システムの役割

```text
[Web UI（一覧 + サイドシート）]
              │
              ▼
        [Flask API]
         │         │
         ▼         ▼
   [JSON ファイル] [data/uploads/]
```

想定ディレクトリ:

```text
data/
  parts.json          # 部品レコード
  columns.json        # カラム定義カタログ
  uploads/            # 添付ファイル実体
```

- **登録・更新・削除**: 部品の CRUD（`name` 必須、他は任意）
- **カラム拡張**: 全体カタログへの追加、レコードへの値設定
- **ファイル添付**: ファイル型カラムに PDF / PNG を複数格納
- **検索・参照**: 横断検索・インラインフィルター・ソート・ページング相当
- **UI**: 一覧 + サイドシートを中心に操作

### API（概要）

JSON を返す REST 風 API とします（詳細パスは実装時に確定してよい）。

| 操作 | 概要 |
|------|------|
| 部品一覧 | `limit` / `offset`、検索・フィルター・ソート用クエリ |
| 部品取得 | `id` 指定 |
| 部品作成・更新・削除 | ボディにフィールド。`name` 必須 |
| カラム定義 | 一覧・追加 |
| ファイル | アップロード・取得・削除 |

infinite scroll は `limit` + `offset` で追加読み込みします。

### 同時書き込み

デモは単一ユーザー想定です。  
JSON 更新時は **簡易ファイルロック** で破損を防ぎます。本格的な同時編集制御は対象外です。

### 設計方針（デモ段階）

1. **軽量優先** — Flask + JSON + vanilla JS で素早くデモ機を作る
2. **名称のみ必須** — それ以外は空欄可
3. **全体カラムカタログ + スパースな値** — 入力時にカラム追加可能、部品ごとに持つ項目は異なってよい
4. **ファイル対応** — ファイル型カラムに PDF / PNG を複数格納
5. **シンプルな UI** — 一覧 + サイドシート中心
6. **一覧表示はユーザ設定** — 名称は固定表示、他は localStorage で表示選択と順序変更
7. **検索・フィルター・ソート** — 横断検索、カラムフィルター、単一カラムソート
8. **API 経由** — 通常操作は API 経由
9. **移行を見据える** — JSON 構造は後から DB へ載せ替えやすい形にする

### 非目標（デモ段階のスコープ外）

- 厳密な固定スキーマ / 必須項目の大量化
- 複雑な画面遷移やダッシュボード化
- RDB / 本格 ORM
- 認証・マルチユーザー・同時編集の高度制御
- モバイル専用 UI 最適化
- 自動バックアップ
- EC サイト連携、CAD 連携、承認フロー、マルチテナント
- JPEG 等の追加形式（必要になったら拡張）

### 起動・配置（デモ）

| 項目 | 方針 |
|------|------|
| 依存関係 | `uv`（`pyproject.toml` / `uv.lock`） |
| ポート | `5050`（macOS の AirPlay が 5000 を占有するため） |
| データ | リポジトリ内 `data/`（uploads 実体は `.gitignore`） |

```bash
cd device_db
uv sync
uv run python scripts/seed_sample_data.py   # 初回のみ（サンプル投入）
uv run python app.py
```

ブラウザで http://127.0.0.1:5050/ を開きます。
